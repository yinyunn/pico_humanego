# exp_0001 —— open_door 学习率实验

### 观察

`exp_0000` 基线在 1 个 epoch、1 个训练 session 和 seed 7 下完成了流程，固定
分数为 `1.5651790074`。当前只有一次基线观察，尚不足以判断学习率敏感性。

### 假设

在保持数据、模型、seed 和评估协议不变的情况下，将学习率提高到 `2e-4` 可能
改善短预算内的优化速度，并降低 open_door 的评估分数。

### 变更

从 `exp_0000` 派生配置，只修改：

```text
lr: 1.0e-4 -> 2.0e-4
```

本次使用 search budget 20 epochs，同时保留 `--data_num 1` 以使用与基线 smoke
相同的第一个训练 session；seed 固定为 7。

### 预期

- 训练和评估流程成功完成；
- 固定 score 低于 `exp_0000` 的 smoke 参考值；
- 不出现 OOM、NaN 或评估错误。

### 结果

实验已成功完成，实际使用 AutoResearch wrapper 运行：

```bash
conda run -n humanego python autoresearch/scripts/run_experiment.py \
  --experiment-id exp_0001 --epochs 20 --data-num 1 \
  --num-workers 0 --device cuda --seed 7
```

- 状态：`SUCCESS`
- 运行时长：`312.60` 秒
- 实际训练：29 个显式训练 session 配置；本次 smoke-style 数据限制为第一个训练 session，共 295 个样本
- 评估：314 帧
- 最终快照：`runs/open_door/autoresearch/exp_0001/eval_snapshots/eval_ep_0020.json`
- `pos_err_w_m`：`0.2669006309`
- `rot_err_w_deg`：`102.8514332213`
- `grasp_f1_w`：`0.4602224607`
- `score`：`1.2493927171`

分数比 `exp_0000` 的 `1.5651790074` 低约 20.2%。不过，`exp_0000` 是 1 epoch
的基线 smoke，而本实验是 20 epoch search budget，因此该改善同时包含训练时长因素，
不能单独归因于学习率变化。

### 决策

`KEEP`：保留为当前 search candidate，并更新 `best.json`。本轮到此停止，不启动
`exp_0002`，也不启动自主研究循环。
